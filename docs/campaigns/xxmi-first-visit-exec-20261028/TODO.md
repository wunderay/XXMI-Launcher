# XXMI first-visit readiness tasks

Use SPEC.md as the acceptance contract. Suggested quest boundaries follow; Questwright may refine them into smaller independently verifiable work without weakening source, execution, runtime or review gates. Do not start every stage as a monolithic quest.

- [ ] Q00 — Bind the existing native and launcher baseline (3–6 h). Inventory exact dirty/untracked inputs and existing build receipts; select only PreparedLoading changes needed for this goal, preserving unrelated installer/antivirus changes. Reconstruct the native bundle/ordered patches in owned scratch, record complete source manifests and exact version header, and place authorized portable source/build inputs where workers can fetch them. Validate the candidate against the current ignored native source and development record. Required before remote dispatch: real repository registration, authorized candidate input identity and qualified executor. Output source manifest, reconstruction procedure, exclusions and meaningful build preflight. Do not deploy. Parent/operator must supply the portable inputs if the assigned executor cannot read the local checkout; do not claim a cloud worker can access an ignored host path.

- [ ] Q01 — Specify bounded coverage events and replay fixtures (2–4 h; after Q00). Define stable generation/resource/group IDs, finite buffers/caps and admission/retry/rejection/end/pressure/eviction/invalidation records. Preserve existing counter meaning and capture compatibility. Acceptance: deterministic example sessions explain each outcome without inventing cause or treating counters as latency. Own telemetry types/contracts and tests; avoid Runtime writer overlap with Q02.

- [ ] Q02 — Implement accountable native outcomes and collector support (3–5 h; after Q01). Instrument existing paths and asynchronous publication with low overhead; connect first-use QPC costs to Present intervals. Acceptance: fixtures cover every reason, pressure transitions, generation changes, loss markers and bounded publication. Own Runtime/trace integration and collector adapter. Report overhead scope honestly.

- [ ] Q03 — Resolve complete supported dependency groups (3–6 h; after Q00; parallel with Q01/Q02 only on disjoint files). Add resource/command dependency closure and explicit unknown/incomplete reasons with compatibility fallback. Acceptance: nested/shared/cyclic or unsupported paths are handled conservatively; inactive on-disk mods are not admitted as active. Own compiler/planner closure module and fixtures; coordinate shared header contract before editing.

- [ ] Q04 — Persist useful bounded observations and rank groups (3–6 h; after Q01/Q03). Separate observation from speculative learning; bind profile to content/config identity; choose complete groups by measured cost/frequency/bytes within existing limits. Acceptance: deterministic ranking, oversized inputs, corrupt/stale profile, generation changes and bounded storage tested. No unvalidated estimate reduction. Own profile/ranking module and fixtures.

- [ ] Q05 — Complete startup preparation and zero-work first use (4–8 h; after Q02/Q03/Q04). Integrate selected closures with actual-device private object/view creation and exact ready reuse during explicit startup only. Acceptance: production-path WARP fixture proves correct complete closure, exact object/view reuse with source reads denied, independent mutations, safe fallback and zero later speculative uploads. Own Runtime/readiness integration; serialize against Q02 and Q06 where files overlap.

- [ ] Q06 — Bound staging lifetime, pressure retention and retries (4–8 h; after Q04/Q05). Release staging only when safe; retain compact immutable verification; rank eviction by groups with explicit byte targets and bounded retries. Acceptance: CPU/GPU caps, pressure/recovery, cancellation, invalidation and revisit behavior covered; GPU hits remain valid after staging release. No game-owned resources released. Own cache/lifetime modules and fixtures; Runtime changes require explicit handoff.

- [ ] Q07 — Integrate coverage display and exact capture protocol (2–4 h; after Q02/Q03; disjoint UI/protocol preparation can run while Q05/Q06 finish). Show selected versus complete coverage/reasons and preserve ordinary user Start flow. Extend existing capture metadata with effective settings, source/DLL identities, selected groups and protocol conditions; preserve originals and completeness/accounting checks. Acceptance: UI/collector changed-contract tests and an honest synthetic protocol example; no automatic game launch, UAC or performance claims.

- [ ] Q08 — Rebuild and independently verify the candidate (4–8 h; after Q05/Q06/Q07). Run full exact-source production and fixture builds plus changed-contract checks using the available resource budget. Bind reports/hashes, verify production exports, preserve mod/normal-installation state, and review rollback/recovery. Fix findings in source, not the acceptance gates. Output implementation/fixture verdict distinct from game qualification.

- [ ] Q09 — User-run matched first-visit qualification and final review (human scheduling external; analysis estimate 2–4 h). Supply one concise, concrete capture procedure and candidate identity; the user launches the game. Compare first versus revisit for verified selected closures and baseline variability; assess visual correctness, startup, F10, revisit and pacing. Require independent exact-evidence acceptance. Missing or inconsistent observations remain NOT PROVEN; do not substitute WARP or aggregate counters. Preserve full release/signing gates separately. While awaiting captures, allow lower-priority campaign work only when no other eligible work remains in the current priority campaign.

Terminal deliverables: portable source/build input identity; implemented bounded native policy and tests; exact candidate build receipts; supported/unsupported coverage report; user-run evidence and independent selected-scenario verdict when available; unresolved gates and reversible recovery instructions. Never mark full campaign performance success solely because Q00–Q08 pass.
