XXMI Capture — portable Windows x64 collector

1. Extract the ZIP into a folder inside your XXMI-Launcher clone.
   Double-click XXMI.Capture.exe.
2. Launch your game. The app automatically detects supported running games.
   If several are running, choose one. Change game lets you choose manually.
3. Click Start capture. Switch back to the game and reproduce the issue.
   The default capture lasts 60 seconds and needs no screenshots or setup paths.
4. Finish the capture early or let the timer finish. Open the report or saved ZIP.

Optional capture settings let you change the duration, scenario, run type,
save folder, diagnostic trace folder, or PresentMon executable. These are
not required for a basic hardware/DLL/process capture.

Automatic detection recognizes Zenless Zone Zero, Genshin Impact, Honkai:
Star Rail, Honkai Impact 3rd, Arknights: Endfield and corroborated Wuthering
Waves game processes. If detection is uncertain, choose the game manually.
An active capture keeps its original target even if other games start.

Screenshots, attachments and observation markers are optional. Expand their
section only if you want to add them. Capturing a screen gives you three
seconds to switch to the game; it does not prove rendering correctness.

For native phase timings, the instrumented diagnostic DLL must already be
installed through your existing development setup. Stock DLLs do not emit
these traces. The collector does not install DLLs or edit configurations.

In the existing [Logging] section of the diagnostic importer's d3dx.ini:
  mod_load_trace = 1
  mod_load_trace_commands = 0
Press F10 to arm. Reproduce one short scenario. Set mod_load_trace = 0 and
press F10 again to export the trace beside that DLL. If export completes
after this app stops, click Refresh exported traces to update the report/ZIP.

PresentMon is optional and separately obtained. If you select a compatible
executable, the app records its version/hash and launches a timed capture
for the selected PID. Permission/tool failures are recorded as unavailable.
No admin elevation, tools download, automatic upload, or game injection occurs.

Default output: <XXMI-Launcher repo>\captures (excluded from Git).
If the app is outside the repo, Start capture asks you to select the repo folder.
Use Open folder to find saved captures.
Every session has its own folder; optional settings let you change its location.
Reports distinguish measured values, missing data, and partial captures.
Manual observations/screenshots do not prove an exact first-correct frame.
Review screenshots and bundle contents before sharing them: metadata and
attachments can contain local paths, account names, and configuration text.

If Windows restricts game access, unavailable process/module measurements are
marked explicitly while other evidence continues. A fully restricted process
cannot be monitored for exit; use Finish & save or wait for the timer. If saving
fails, the error names the operation and folder. Choose a writable save folder
in optional settings. Copy error details copies the technical error locally;
review its paths before sharing. No administrator launch is required by the app.

Runtime: Windows 10/11 x64 with .NET Framework 4.8 (normally included).
No Python or .NET SDK is needed to run the prebuilt app.

This build compiles for Windows; portable logic and synthetic native Windows
UI checks passed. Real game/WMI/PresentMon/screenshot capture and actual monitor
DPI/high-contrast behavior still need local qualification. No game performance
improvement or acceptance verdict is claimed.
