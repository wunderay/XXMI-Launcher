XXMI Capture — portable Windows x64 collector

1. Extract the ZIP to a folder. Double-click XXMI.Capture.exe.
2. Launch your game, click Refresh, and select its process.
3. Optionally choose the diagnostic DLL's trace folder and PresentMon.exe.
   Leave these blank for hardware/DLL/process evidence only.
4. Choose a scenario, Baseline/Candidate/Investigation, and duration.
5. Click Start capture. Reproduce the issue. Add observation markers or
   click Capture game screen (a three-second delay lets you switch back).
6. Click Finish & save, or allow the timer to finish. Open the HTML report.
   A ZIP beside the capture folder contains the recorded evidence.

For native phase timings, the instrumented diagnostic DLL must already be
installed through your existing development setup. Stock DLLs do not emit
these traces. The collector does not install DLLs or edit configurations.

In the existing [Logging] section of the diagnostic importer's d3dx.ini:
  mod_load_trace = 1
  mod_load_trace_commands = 0
Press F10 to arm. Reproduce one short scenario. Set mod_load_trace = 0 and
press F10 again to export the trace beside that DLL. If export completes
after this app stops, click Refresh exported traces to update the report/ZIP.

PresentMon is optional and separately obtained. If you select a compatible
executable, the app records its version/hash and launches a timed capture
for the selected PID. Permission/tool failures are recorded as unavailable.
No admin elevation, tools download, automatic upload, or game injection occurs.

Default output: Documents\XXMI Captures. Every session has its own folder.
Reports distinguish measured values, missing data, and partial captures.
Manual observations/screenshots do not prove an exact first-correct frame.
Review screenshots and bundle contents before sharing them: metadata and
attachments can contain local paths, account names, and configuration text.

Runtime: Windows 10/11 x64 with .NET Framework 4.8 (normally included).
No Python or .NET SDK is needed to run the prebuilt app.

This build was compiled for Windows and portable logic was tested on Linux.
Its actual Windows UI/WMI/PresentMon/screenshot behavior still needs a local
smoke test. No game performance improvement or acceptance verdict is claimed.
